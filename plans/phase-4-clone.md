# Phase 4 — `trunk clone`

**Goal.** The full path from a remote URL to a configured, tested, committed project. Every
other command is a variation of this pipeline.

**Depends on.** Phases 1–3.

**Deliverables.**

```
source/commands/clone.tsx      the pipeline
source/core/journal.ts         records what this run created (for rollback/resume)
source/core/wt.ts              wt wrappers, including terminal pass-through
source/core/gh.ts              PR creation
test/e2e-clone.test.ts         file:// remote, --yes, end to end
```

## Pipeline

Each numbered step appends to the **journal** (`journal.ts`) before it acts, so step 12 can
describe or undo precisely what exists.

1. **Preflight.** Platform check; `git` and `wt` present; parse the URL (phase 1); resolve
   the target folder: `[dir]` argument, else `./<remote repo name>` (D18). Refuse a folder
   that exists and is not empty (exit `2`).
2. **Bare clone.** `git clone --bare <url> <dir>/.git`. Stream progress through the reporter.
3. **Fix the refspec.** A bare clone has none, which previously broke `wt step copy-ignored`:

   ```sh
   git --git-dir <dir>/.git config remote.origin.fetch '+refs/heads/*:refs/remotes/origin/*'
   git --git-dir <dir>/.git fetch origin --prune
   ```
4. **Default branch.** `git ls-remote --symref origin HEAD` → e.g. `main`. Record it, and
   make sure `HEAD` in the bare repo points at it (`git symbolic-ref HEAD refs/heads/<b>`).
5. **First worktree, with the terminal attached** (D3, D4). Run `wt switch <default>` as a
   child process with `stdio: 'inherit'` from the project directory, so **wt's own**
   worktree-path question reaches the user. trunk writes nothing into the user's worktrunk
   config, ever.
   - No TTY: skip the pass-through, create the worktree with
     `git --git-dir <dir>/.git worktree add <dir>/<default> <default>`, and warn:

     ```
     ⚠ worktree-path is not configured for <identifier>.
       Agents and scripts will create <dir>/.git.<branch> instead of <dir>/<branch>.
       Fix: run `wt switch <branch>` in a terminal once, or add to ~/.config/worktrunk/config.toml:
         [projects."<identifier>"]
         worktree-path = "{{ repo_path }}/../{{ branch | sanitize }}"
     ```
   - Afterwards, verify where the worktree actually landed (`git worktree list`). If it is
     `.git.<branch>`, print the same warning with the real path.
6. **Existing config check** (D9). If `<default>/.config/wt.toml` exists:
   - interactive → ask `keep / overwrite`;
   - `--yes` → keep;
   - keep ends the run at step 11 (approvals and smoke test still offered), reporting
     `wt.toml exists → kept`.
7. **Detect and resolve** (phases 1 and 3) inside the default worktree: package manager,
   scripts, app directory. Then the form or `--yes`.
8. **Setup worktree** (D5). Unless `--direct`:

   ```sh
   wt switch --create chore/trunk-setup --no-hooks     # from the project dir
   ```

   `--no-hooks` matters: the config being written is not yet approved, and the hooks would
   run against a half-configured repo. With `--direct`, work happens in the default worktree.
9. **Write and validate** (D17). Write `.config/wt.toml` (creating `.config/`), then run
   `wt config show` and `wt hook show --expanded` in that worktree. On any error or warning:
   show the output with the offending lines, do not commit, and jump to step 12.
   On success, print the rendered preview (session, port, URL) and ask to commit.
10. **Commit and PR.** Commit only `.config/wt.toml`:

    ```
    Add worktree automation

    Generated by trunk <version>: tmux session, dependency install, dev server and
    Caddy route for each worktree. Run `wt config approvals add` after checking out.
    ```

    Then ask `push and open a PR?`. With `gh` present and a GitHub remote:
    `git push -u origin chore/trunk-setup` and `gh pr create --fill`. Without `gh`, push and
    print the compare URL. `--yes` pushes and opens the PR only when `--pr` is also passed;
    otherwise it stops after the commit and prints the two commands.
11. **Approvals and smoke test** (D18). Offer, in order:
    - `wt config approvals add` (run with the terminal attached; it is interactive),
    - `wt hook pre-start` then `wt hook post-start` in the setup worktree.

    Report each step's result, and on failure print the log path
    (`.git/wt/logs/<branch>/project/post-start/`). A failed smoke test does not undo the
    commit; it is reported and the run ends with exit `1`.
12. **Interrupted runs** (D19). Any failure or abort lands here with the journal:

    ```
    ✗ validation failed in chore-trunk-setup
      created by this run:
        ./acme-admin/.git              bare repo
        ./acme-admin/main              worktree
        ./acme-admin/chore-trunk-setup worktree + branch (wt.toml uncommitted)
    ? keep, or roll back what this run created? (keep/rollback)
    ```

    - keep → print `resume: trunk init ./acme-admin` plus the manual undo commands;
    - rollback → remove in reverse order: `wt remove chore/trunk-setup --no-hooks --yes`,
      `git worktree remove`, and finally the project folder **only if trunk created it**;
    - no TTY → always keep, print both command sets (D19).

## Acceptance criteria

- [ ] End to end against a local `file://` bare remote with `--yes`: folder, bare `.git`,
      fetch refspec set, `origin/*` refs present, default worktree, `chore/trunk-setup`
      worktree with a committed `.config/wt.toml`, and `wt config show` clean.
- [ ] `git --git-dir <dir>/.git config remote.origin.fetch` returns the standard refspec.
- [ ] A repo whose default branch is `master` is handled without a hardcoded `main`.
- [ ] Re-running `trunk clone` into an existing non-empty folder exits `2` and changes nothing.
- [ ] With an existing `wt.toml` and `--yes`, the file is untouched (byte comparison).
- [ ] With no TTY, the `.git.<branch>` warning text appears and includes the real identifier.
- [ ] Simulated validation failure leaves no commit, and the keep/rollback prompt lists
      exactly what the journal recorded.
- [ ] Rollback removes the setup worktree and branch, and leaves no `.git/wt/trash` surprises
      for a folder trunk did not create.

## Risks & notes

- Never `cd`. Every git call uses `--git-dir` / `-C`, and every wt call uses `wt -C <path>`,
  which also keeps the code safe inside another worktree.
- `wt switch --create` runs hooks by default; `--no-hooks` is mandatory here.
- The smoke test starts a real dev server and a real Caddy route. Say so before running it,
  and print how to stop them (`wt remove`, or the `up`/`url` aliases) afterwards.
- `gh pr create --fill` uses the commit message; keep the commit body useful for teammates,
  since it becomes the PR description.
