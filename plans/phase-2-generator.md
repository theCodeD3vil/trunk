# Phase 2 — The `wt.toml` generator

**Goal.** A pure function from a settings object to the text of `.config/wt.toml`, plus the
validation that proves the result is good. This is the heart of trunk; everything else is
plumbing around it.

**Depends on.** Phase 1.

**Deliverables.**

```
source/core/settings.ts          the Settings type + defaults
source/core/generate/index.ts    compose(settings) -> string
source/core/generate/header.ts
source/core/generate/tmux.ts     pre-start tmux + pre-remove tmux
source/core/generate/steps.ts    copy-ignored, install, server
source/core/generate/proxy.ts    caddy proxy + url print + list.url + pre-remove route
source/core/generate/aliases.ts  up, url, mc
source/core/validate.ts          wt config show / wt hook show --expanded
test/snapshots/*                 generated files per combination
test/shellcheck.test.ts
```

## Steps

1. **Settings type.** Everything the generator needs, and nothing else:

   ```ts
   type Settings = {
     trunkVersion: string;
     generatedOn: string;          // YYYY-MM-DD
     repoName: string;             // remote repo name, e.g. acme-admin
     hostLabel: string;            // repoName.toLowerCase(), used in list.url
     prefix: string;               // acme-a
     pm: 'npm' | 'pnpm' | 'bun';
     appDir?: string;              // when package.json is not at the root
     tmux: boolean;
     agents: AgentId[];            // [] when agents are off; max 4
     editorWindow: true;           // fixed (D13)
     copyIgnored: boolean;
     server: boolean;
     caddy: boolean;               // only meaningful when server is true
     mcAlias: boolean;
     devScript: string;            // default 'dev'
     scripts: string[];            // for the comment notes
   };
   ```

   The generator must be **deterministic**: same settings in, byte-identical file out. No
   `Date.now()` inside; `generatedOn` is passed in.

2. **Composition order.** The file is assembled as: header → `[aliases]` → `[[pre-start]]`
   entries → `[[post-start]]` entries → `[pre-remove]` → `[step.copy-ignored]` → `[list]`.
   A step that is off contributes nothing at all — no commented-out block, no empty table
   (`--no-tmux` must not leave a `[pre-remove]` with only a proxy line and a stray comment).

3. **Header** (D16). Tailored: list only the `WT_*` variables for steps that exist, name the
   detected package manager and the chosen agents, and keep the warnings that matter.

   ```
   # Worktree automation shared by everyone on this repo.
   #
   # Generated by trunk <version> on <date> — edit it freely; trunk won't touch it again.
   #
   # Setup on a new machine: install worktrunk (`wt`) with its shell integration, then run
   # `wt config approvals add` here (again whenever this file changes).
   # tmux, caddy, claude and codex are optional: each step skips itself when its tool is
   # missing. Each machine can tune it with env vars in the shell profile:
   #
   #   WT_TMUX=off            no tmux session
   #   WT_AGENTS="claude"     agents started in the Agents window
   #                          (default "claude codex"; "" starts none; max 4)
   #   WT_EDITOR=hx           editor in the Editor window (default $EDITOR, then nvim)
   #   WT_PROXY=off           no Caddy route
   #
   # P is this repo's tmux session prefix; keep it unique across your repos.
   # Hook bodies are POSIX sh. Avoid "{{", "{%" and "{#" in shell code (e.g. ${#var}):
   # worktrunk reads them as template syntax.
   ```

4. **tmux pre-start** (`tmux.ts`). Start from today's hand-written hook, which is known to
   work, and change only what the decisions require:
   - `P=<prefix>`, `B={{ branch | sanitize }}`, `W={{ worktree_path }}`, `S="${P}_$B"`.
   - Keep the `CLAUDE*` environment scrub, extended to every agent that leaks session state:
     strip `CLAUDE*`, `ANTHROPIC*`, `OPENCODE*`, `CODEX*`, `COPILOT*` before the tmux server
     can inherit them.
   - Keep the `has-session` + `session_path` comparison and the `-t "=$S"` exact targeting
     everywhere (prefix matching killed `fix-ui` once).
   - Windows: `Editor` (index 1), `Agents` (only when `agents.length > 0`), `Terminal` split
     into two panes and selected last. Target windows by id, never by name.
   - Agent loop with the layout rule (D12) and the cap of 4:

     ```sh
     n=0
     for a in ${WT_AGENTS-claude codex}; do
       [ $n -ge 4 ] && echo "… only the first 4 agents are started" && break
       cmd=$a; [ "$a" = antigravity ] && cmd=agy
       command -v "$cmd" >/dev/null 2>&1 || continue
       [ $n -gt 0 ] && tmux split-window -h -t "$AG_W" -c "$W"
       tmux send-keys -t "$AG_W" "$cmd" Enter
       n=$((n + 1))
     done
     [ $n -eq 2 ] && tmux select-layout -t "$AG_W" even-horizontal >/dev/null
     [ $n -gt 2 ] && tmux select-layout -t "$AG_W" tiled >/dev/null
     ```

   - End with the report line, never a failing exit: a failed `pre-start` silently skips
     install and the dev server.

5. **tmux pre-remove.** Today's body unchanged in substance: TERM the pane process trees
   (skipping `$TMUX_PANE`), then a delayed `tmux run-shell -b -d 3` that KILLs and
   `kill-session -t "=$S"`. Keep the space-separated pid list (tmux drops `run-shell`
   commands containing newlines) and keep the comment explaining why.

6. **post-start steps** (`steps.ts`), in this order:
   - `copy = "wt step copy-ignored"` when enabled, **before** install so install only tops up.
   - `install`, by package manager:
     `npm install --prefer-offline --no-audit --no-fund` ·
     `pnpm install --prefer-offline` · `bun install`.
     With `appDir`, prefix accordingly (`npm --prefix backend install`, `pnpm --dir backend`,
     `cd backend && bun install`).
   - `server`, wrapped in `wt step tether --` so the dev server dies with the worktree, with
     the port from `{{ (remote_repo ~ '/' ~ branch) | hash_port }}` and **per-package-manager
     argument syntax** (D14, verified):
     `npm run dev -- --port <port>` · `pnpm run dev --port <port>` · `bun run dev --port <port>`.
     Above it, the comment notes:

     ```
     # Dev server; `wt step tether` stops it when the worktree is removed, however it is
     # removed. The port hashes repo + branch, so the same branch in two repos gets two ports.
     # Adjust the command if this project needs something else:
     #   port from the environment (Nest, Express):  PORT=<port> <pm> run start:dev
     #   another script:                             <pm> run <script> --port <port>
     #   app in a subfolder:                         <pm> --dir backend run dev --port <port>
     # (pnpm passes a literal "--" through, so don't write `pnpm run dev -- --port`.)
     ```

     List the repo's real `scripts` names in that note when they were detected.
   - `proxy` when caddy is on: today's Caddy admin-API body with
     `ID=wt:{{ remote_repo | lower }}:{{ branch | sanitize }}`.

7. **URL print and list** (`proxy.ts`). The `↗ Local server: …` line stays in `[[pre-start]]`,
   because post-start output only reaches the log. `[list] url` writes the host label out
   literally (`http://{{ branch | sanitize }}.<hostLabel>.localhost:8080`) since repo
   variables render the whole URL empty there. Never emit `[list] summary` in project config;
   wt warns that it belongs in user config.

8. **Aliases** (`aliases.ts`). `up` (re-run pre-start plus the server and proxy steps) and
   `url` (with the `{% if args %}` branch) are included whenever their steps exist. `mc` is
   included when `settings.mcAlias`. Keep the `mc` body exactly as today; it is quoted shell
   inside quoted TOML and is easy to break.

9. **Escaping rules.** One helper does all TOML string emission:
   multi-line bodies use `'''…'''`, and the generator asserts that no body contains `'''`.
   Shell code must never contain `{{`, `{%`, `{#`, or `${#var}`. Add a unit test that scans
   every generated body for those sequences and fails with the offending line.

10. **Validation** (`validate.ts`). Run inside a worktree that holds the new file:
    - `wt config show` → non-zero exit, `error`, or `warning` lines fail validation;
      surface the raw output.
    - `wt hook show --expanded` → capture the rendered bodies, confirm every configured hook
      is present, and extract the rendered session name, port and URL for the preview.
    - Both are read-only, so they are safe to run before committing.

11. **Shellcheck in tests.** Parse the generated TOML, extract each hook body, write it to a
    temp file with a `#!/bin/sh` shebang and run `shellcheck -s sh`. Treat warnings as
    failures, with a documented ignore list (e.g. SC2086 where word splitting is intended in
    the agent loop) declared per body, not globally.

## Acceptance criteria

- [ ] `compose()` is deterministic and snapshot-tested for: npm/pnpm/bun × server on/off ×
      caddy on/off × agents 0/1/2/3/4 × copy-ignored on/off × mc on/off (a representative
      matrix, not the full cross-product).
- [ ] Every hook body in every snapshot passes `shellcheck -s sh`.
- [ ] No generated body contains `{{`, `{%`, `{#` or `'''`.
- [ ] Turning a step off removes its table entirely; the file always parses as TOML.
- [ ] `wt config show` reports no warnings for every snapshot, checked in a temp bare repo
      with `WORKTRUNK_CONFIG_PATH` pointed at a temp file.
- [ ] `wt hook show --expanded` renders the expected session name, port and URL for a fixed
      repo/branch pair.
- [ ] Generating for `Web-shop--portal` yields `[list] url` with `web-shop--portal`
      written out, and Caddy ids of the form `wt:web-shop--portal:<branch>`.

## Risks & notes

- The existing hand-written file is the reference implementation: port it first, get the
  snapshots green, and only then parameterise. Every difference from it should be traceable
  to a decision.
- `hash_port` gives a per repo+branch port; do not substitute a computed number at generation
  time, or two worktrees of the same branch in different repos would collide.
- Agent names in `WT_AGENTS` are ids, and `antigravity` maps to the `agy` command inside the
  loop. Keep that mapping in one place in the template.
