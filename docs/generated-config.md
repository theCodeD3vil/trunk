# Generated Worktrunk Configuration

`trunk` writes `.config/wt.toml` once, validates it, and commits it. From then on it belongs to the repository: edit it whenever the project workflow changes.

Worktrunk treats project hooks as trusted code. Every contributor must review the file and run:

```sh
wt config approvals add
```

Run that command again whenever `.config/wt.toml` changes.

The blocks below are emitted verbatim by trunk 0.1.0 for an npm project named `Web-shop--portal` with tmux, Claude, Codex, copied ignored files, a development server, Caddy, and all aliases enabled. A project's choices can omit entire blocks or change package-manager commands.

## Header And Machine Overrides

```toml
# Worktree automation shared by everyone on this repo.
#
# Generated by trunk 0.1.0 on 2026-09-18 — edit it freely; trunk won't touch it again.
#
# Setup on a new machine: install worktrunk (`wt`) with its shell integration, then run
# `wt config approvals add` here (again whenever this file changes).
# Package manager: npm.
# tmux, caddy, claude, and codex are optional; each step skips itself when its tool is missing.
# Each machine can tune the optional steps with env vars in its shell profile:
#
#   WT_TMUX=off            no tmux session
#   WT_AGENTS="claude codex" agents started in the Agents window
#                          (default "claude codex"; "" starts none; max 4)
#   WT_EDITOR=hx           editor in the Editor window (default $EDITOR, then nvim)
#   WT_PROXY=off           no Caddy route
#
# P is this repo's tmux session prefix; keep it unique across your repos.
# Hook bodies are POSIX sh. Worktrunk template expressions are intentional; avoid
# introducing shell forms that collide with them (notably shell length expansion).
```

The `WT_*` variables are per-machine escape hatches. They do not change the committed file:

| Variable                   | Behavior                                                  |
| -------------------------- | --------------------------------------------------------- |
| `WT_TMUX=off`              | Skip creating the tmux workspace                          |
| `WT_AGENTS="claude codex"` | Override the selected agents; an empty string starts none |
| `WT_EDITOR=hx`             | Override the editor command used in the Editor window     |
| `WT_PROXY=off`             | Skip creating the Caddy route                             |

Missing optional tools also skip their own work instead of failing the entire hook.

## Aliases

```toml
[aliases]
up = "wt hook pre-start && wt hook post-start server proxy"
url = '''
{% if args %}BRANCH={{ args[0] | sanitize }}{% else %}BRANCH={{ branch | sanitize }}{% endif %}
HOST_SUFFIX=.web-shop--portal.localhost:8080
URL="http://${BRANCH}${HOST_SUFFIX}"
if command -v open >/dev/null 2>&1; then
  open "$URL"
elif command -v xdg-open >/dev/null 2>&1; then
  xdg-open "$URL"
else
  printf '%s\n' "$URL"
fi
'''
mc = '''
WORKTRUNK_COMMIT__GENERATION__COMMAND='f=$(mktemp); printf "\n\n" > "$f"; sed "s/^/# /" >> "$f"; ${EDITOR:-vi} "$f" < /dev/tty > /dev/tty; grep -v "^#" "$f"' wt merge
'''
```

`wt up` reruns only the startup pieces that need restarting. `wt url [branch]` opens a worktree URL on macOS or Linux and prints it elsewhere. `wt mc` opens an editor for the merge commit message before invoking `wt merge`.

## Tmux Pre-Start

```toml
[[pre-start]]
tmux = '''
command -v tmux >/dev/null 2>&1 || { echo "tmux not found; skipping session"; exit 0; }
[ "${WT_TMUX-on}" = off ] && exit 0
P=web-sp
B={{ branch | sanitize }}
W={{ worktree_path }}
S="${P}_$B"

# Remove agent credentials before a new tmux server can inherit them.
for name in $(env | cut -d= -f1); do
  case $name in
    CLAUDE*|ANTHROPIC*|OPENCODE*|CODEX*|COPILOT*) unset "$name" ;;
  esac
done

if tmux has-session -t "=$S" 2>/dev/null; then
  session_path=$(tmux display-message -p -t "=$S" '#{session_path}')
  if [ "$session_path" = "$W" ]; then
    echo "tmux session $S already exists"
    exit 0
  fi
  tmux kill-session -t "=$S" 2>/dev/null || true
fi

if ! tmux new-session -d -s "$S" -c "$W" -n Editor; then
  echo "could not create tmux session $S"
  exit 0
fi
ED_W=$(tmux display-message -p -t "=$S:1" '#{window_id}')
editor=${WT_EDITOR-${EDITOR-nvim}}
if [ -n "$editor" ] && command -v "$editor" >/dev/null 2>&1; then
  tmux send-keys -t "$ED_W" "$editor" Enter
fi
AG_W=$(tmux new-window -P -F '#{window_id}' -t "=$S" -c "$W" -n Agents)
n=0
for a in ${WT_AGENTS-claude codex}; do
  [ "$n" -ge 4 ] && echo "only the first 4 agents are started" && break
  cmd=$a
  [ "$a" = antigravity ] && cmd=agy
  command -v "$cmd" >/dev/null 2>&1 || continue
  [ "$n" -gt 0 ] && tmux split-window -h -t "$AG_W" -c "$W"
  tmux send-keys -t "$AG_W" "$cmd" Enter
  n=$((n + 1))
done
[ "$n" -eq 2 ] && tmux select-layout -t "$AG_W" even-horizontal >/dev/null
[ "$n" -gt 2 ] && tmux select-layout -t "$AG_W" tiled >/dev/null
TERM_W=$(tmux new-window -P -F '#{window_id}' -t "=$S" -c "$W" -n Terminal)
tmux split-window -h -t "$TERM_W" -c "$W"
tmux select-window -t "$TERM_W"
printf 'tmux session %s ready; attach with: tmux attach -t =%s\n' "$S" "$S"
'''
```

The leading `=` in every `-t "=$S"` target forces an exact tmux session-name match. Without it, tmux accepts prefixes: removing `fix-ui` could accidentally target `fix-ui-tests`.

The hook compares an existing session's path before reusing it, opens deterministic Editor, Agents, and Terminal windows, and strips agent credentials before a new tmux server can inherit them. Agent ids normally equal their commands; `antigravity` maps to `agy`.

## URL Pre-Start

```toml
[[pre-start]]
url = '''
BRANCH={{ branch | sanitize }}
HOST_SUFFIX=.web-shop--portal.localhost:8080
URL="http://${BRANCH}${HOST_SUFFIX}"
printf '↗ Local server: %s\n' "$URL"
'''
```

The URL is printed from `pre-start` deliberately. Worktrunk displays that output in the terminal, while `post-start` output goes only to the hook log. The server may not be ready at this exact moment; the line tells the user which stable URL it will use.

## Copy And Install

```toml
[[post-start]]
copy = "wt step copy-ignored"

[[post-start]]
install = "npm install --prefer-offline --no-audit --no-fund"
```

Copied ignored files come first so the package-manager install only fills what is missing. For pnpm and Bun projects trunk emits their native install commands, including the selected app subdirectory when the package lives below the repository root.

## Server And Caddy Route

```toml
# Dev server; `wt step tether` stops it when the worktree is removed, however it is
# removed. The port hashes repo + branch, so the same branch in two repos gets two ports.
# Adjust the command if this project needs something else:
#   port from the environment (Nest, Express):  PORT=<port> npm run start:dev
#   another script:                             npm run <script> --port <port>
# Detected package scripts: build, dev, lint
[[post-start]]
server = "wt step tether -- npm run dev -- --port {{ (remote_repo ~ '/' ~ branch) | hash_port }}"
proxy = '''
[ "${WT_PROXY-on}" = off ] && exit 0
command -v caddy >/dev/null 2>&1 || { echo "caddy not found; skipping proxy"; exit 0; }
command -v curl >/dev/null 2>&1 || { echo "curl not found; skipping proxy"; exit 0; }
ID=wt:{{ remote_repo | lower }}:{{ branch | sanitize }}
HOST={{ branch | sanitize }}.{{ remote_repo | lower }}.localhost
PORT={{ (remote_repo ~ '/' ~ branch) | hash_port }}
curl -sf --max-time 0.5 http://localhost:2019/config/ >/dev/null || caddy start
curl -sf http://localhost:2019/config/apps/http/servers/wt >/dev/null || \
  curl -sfX PUT http://localhost:2019/config/apps/http/servers/wt \
    -H 'Content-Type: application/json' \
    -d '{"listen":[":8080"],"automatic_https":{"disable":true},"routes":[]}'
curl -sf -X DELETE "http://localhost:2019/id/$ID" >/dev/null || true
PAYLOAD=$(printf '{"@id":"%s","match":[{"host":["%s"]}],"handle":[{"handler":"reverse_proxy","upstreams":[{"dial":"127.0.0.1:%s"}]}]}' "$ID" "$HOST" "$PORT")
curl -sfX PUT http://localhost:2019/config/apps/http/servers/wt/routes/0 \
  -H 'Content-Type: application/json' \
  -d "$PAYLOAD"
'''
```

`wt step tether` owns the development-server process so removing a worktree also stops its server. The port hashes `remote_repo + branch`, not just the branch: two repositories can both have a `main` worktree without competing for one port. The same expression feeds the server and Caddy, so they cannot drift apart.

The Caddy route id also contains the repository and branch. Re-running the hook deletes that exact old route before adding its replacement.

## Pre-Remove Cleanup

```toml
[pre-remove]
tmux = '''
command -v tmux >/dev/null 2>&1 || exit 0
P=web-sp
B={{ branch | sanitize }}
S="${P}_$B"
tmux has-session -t "=$S" 2>/dev/null || exit 0
PIDS=
collect_tree() {
  parent=$1
  for child in $(pgrep -P "$parent" 2>/dev/null); do
    collect_tree "$child"
  done
  PIDS="$PIDS $parent"
}
for pane in $(tmux list-panes -s -t "=$S" -F '#{pane_id}'); do
  [ "$pane" = "${TMUX_PANE-}" ] && continue
  pane_pid=$(tmux display-message -p -t "$pane" '#{pane_pid}')
  [ -n "$pane_pid" ] && collect_tree "$pane_pid"
done
if [ -n "$PIDS" ]; then
  kill -TERM $PIDS 2>/dev/null || true
fi
# Keep this delayed command on one line: tmux drops run-shell commands containing newlines.
tmux run-shell -b -d 3 "if [ -n '$PIDS' ]; then kill -KILL $PIDS 2>/dev/null || true; fi; tmux kill-session -t '=$S' 2>/dev/null || true"
'''
proxy = '''
command -v curl >/dev/null 2>&1 || exit 0
ID=wt:{{ remote_repo | lower }}:{{ branch | sanitize }}
curl -sf -X DELETE "http://localhost:2019/id/$ID" >/dev/null || true
'''
```

The tmux cleanup walks each pane's process tree, sends `TERM`, waits three seconds, and then sends `KILL` before deleting the exact session. It skips the pane currently running the removal command. The proxy cleanup removes only this worktree's route.

## Worktree List URL

```toml
[list]
url = "http://{{ branch | sanitize }}.web-shop--portal.localhost:8080"
```

The repository host label is written out literally here. Worktrunk does not expose repository variables in `[list]`; using `{{ remote_repo }}` would render the entire URL empty. The branch remains a template because it varies for each row.

For `trunk new --no-remote`, every remote-dependent value is written with the literal project name and the header explains how to switch back to `remote_repo` after adding `origin`.

## Changing The File

Common edits are changing the development command, setting a framework-specific port variable, removing a hook the project does not use, or adding project-specific setup. Keep hook bodies valid POSIX `sh`, then validate the result:

```sh
wt config show
wt hook show --expanded
wt config approvals add
```
