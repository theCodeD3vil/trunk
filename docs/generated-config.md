# Generated Worktrunk Configuration

`trunk` writes `.config/wt.toml` once, validates it with Worktrunk, and commits it. From then on it belongs to the repository: edit it whenever the project workflow changes. `trunk` never rewrites it on its own; `trunk-cli init` only replaces it after showing you a diff and getting your confirmation, and `--yes` always keeps the file that is there.

The file is language-agnostic. It sets up the worktree experience (a tmux workspace per worktree, optional copying of ignored files, two convenience aliases) and says nothing about how your project is built or run. Project-specific setup, such as installing dependencies or starting a server, is added by hand; `trunk-cli docs` has copyable recipes.

Worktrunk treats project hooks as trusted code. Every contributor must review the file and run:

```sh
wt config approvals add
```

Run that command again whenever `.config/wt.toml` changes.

The blocks below are emitted verbatim by `trunk-cli` for a repository named `storefront` with tmux, the Claude and Codex agents, copied ignored files, and the `mc` alias all enabled. The version and date in the header vary per run. Other choices omit whole blocks, as described under [Choices that change the file](#choices-that-change-the-file).

## Header And Machine Overrides

```toml
# Worktree automation shared by everyone on this repo.
#
# Generated by trunk-cli <version> on <date> — edit it freely; trunk only rewrites it if you ask.
# Add project-specific setup as hooks below; `trunk-cli docs` has recipes.
#
# Setup on a new machine: install worktrunk (`wt`) with its shell integration, then run
# `wt config approvals add` here (again whenever this file changes).
# tmux, claude, and codex are optional; each step skips itself when its tool is missing.
#
# Each machine can tune the tmux workspace with env vars in its shell profile:
#
#   WT_TMUX=off            no tmux session
#   WT_AGENTS="claude codex" agents started in the Agents window
#                          (default "claude codex"; "" starts none; max 4)
#   WT_EDITOR=hx           editor in the Editor window (default $EDITOR, then nvim)
#
# P is this repo's tmux session prefix; keep it unique across your repos.
# Hook bodies are POSIX sh. Worktrunk template expressions are intentional; avoid
# introducing shell forms that collide with them (notably shell length expansion).
```

The `WT_*` variables are per-machine escape hatches. They do not change the committed file:

| Variable                   | Behavior                                                  |
| -------------------------- | --------------------------------------------------------- |
| `WT_TMUX=off`              | Skip creating the tmux workspace                          |
| `WT_AGENTS="claude codex"` | Override the selected agents; an empty string starts none |
| `WT_EDITOR=hx`             | Override the editor command used in the Editor window     |

A missing optional tool, such as tmux or an agent, skips its own work instead of failing the whole hook. `trunk-cli` does not clear or change any environment variable an agent inherits.

## Aliases

```toml
[aliases]
up = "wt hook pre-start"
mc = '''
WORKTRUNK_COMMIT__GENERATION__COMMAND='f=$(mktemp); printf "\n\n" > "$f"; sed "s/^/# /" >> "$f"; ${EDITOR:-vi} "$f" < /dev/tty > /dev/tty; grep -v "^#" "$f"' wt merge
'''
```

- `wt up` runs the start hooks again. It is only generated when there is a start hook to run, and is useful in a worktree that predates the config or whose tmux session you closed.
- `wt mc` runs `wt merge` and opens `$EDITOR` for the commit message. It is on by default and can be turned off with `--no-mc`.

## Start: Copy, Then tmux

Worktrunk runs `[[pre-start]]` blocks one after another and waits for each, so files are in place before the session opens on them.

```toml
[[pre-start]]
copy = "wt step copy-ignored"
```

`wt step copy-ignored` copies gitignored files, such as caches and local configuration, from the primary worktree. It is off by default and enabled with `--copy`. When it is off, no copy hook exists.

```toml
[[pre-start]]
tmux = '''
command -v tmux >/dev/null 2>&1 || { echo "tmux not found; skipping session"; exit 0; }
[ "${WT_TMUX-on}" = off ] && exit 0
P=storefront
B={{ branch | sanitize }}
W={{ worktree_path }}
S="${P}_$B"
owned_session() {
  for id in $(tmux list-sessions -F '#{session_id}' 2>/dev/null); do
    [ "$(tmux show-options -qv -t "$id" @twt 2>/dev/null)" = "$W" ] && { echo "$id"; return; }
  done
}

SID=$(owned_session)
if [ -n "$SID" ]; then
  echo "tmux session $(tmux display-message -p -t "$SID" '#{session_name}') already exists"
  exit 0
fi

if tmux has-session -t "=$S" 2>/dev/null; then
  SID=$(tmux display-message -p -t "=$S:" '#{session_id}')
  owner=$(tmux show-options -qv -t "$SID" @twt 2>/dev/null)
  if [ -n "$owner" ] && [ -d "$owner" ]; then
    echo "tmux session $S belongs to $owner; not creating one for this worktree"
    exit 0
  fi
  session_path=$(tmux display-message -p -t "$SID" '#{session_path}')
  if [ "$session_path" = "$W" ]; then
    tmux set-option -t "$SID" @twt "$W"
    echo "tmux session $S already exists"
    exit 0
  fi
  tmux kill-session -t "$SID" 2>/dev/null || true
fi

if ! SID=$(tmux new-session -d -P -F '#{session_id}' -s "$S" -c "$W" -n Editor); then
  echo "could not create tmux session $S"
  exit 0
fi
tmux set-option -t "$SID" @twt "$W"
ED_W=$(tmux display-message -p -t "=$S:1" '#{window_id}')
editor=${WT_EDITOR-${EDITOR-nvim}}
if [ -n "$editor" ] && command -v "$editor" >/dev/null 2>&1; then
  tmux send-keys -t "$ED_W" "$editor" Enter
fi
AG_W=$(tmux new-window -P -F '#{window_id}' -t "=$S" -c "$W" -n Agents)
n=0
for a in ${WT_AGENTS-claude codex}; do
  [ "$n" -ge 4 ] && echo "only the first 4 agents are started" && break
  cmd=$a
  [ "$a" = antigravity ] && cmd=agy
  command -v "$cmd" >/dev/null 2>&1 || continue
  [ "$n" -gt 0 ] && tmux split-window -h -t "$AG_W" -c "$W"
  tmux send-keys -t "$AG_W" "$cmd" Enter
  n=$((n + 1))
done
[ "$n" -eq 2 ] && tmux select-layout -t "$AG_W" even-horizontal >/dev/null
[ "$n" -gt 2 ] && tmux select-layout -t "$AG_W" tiled >/dev/null
TERM_W=$(tmux new-window -P -F '#{window_id}' -t "=$S" -c "$W" -n Terminal)
tmux split-window -h -t "$TERM_W" -c "$W"
tmux select-window -t "$TERM_W"
printf 'tmux session %s ready; attach with: tmux attach -t =%s\n' "$S" "$S"
'''
```

The session is named `<prefix>_<branch>`, for example `storefront_main`. The prefix is chosen during setup (`--prefix`), defaults to the initials of the repository name, and should be unique across your repositories. 

The session is also tagged with the worktree's path, in a tmux option called `@twt`. Every hook finds the session by that tag first, so you can rename it whenever you like (`prefix + $` in tmux) and starting, stopping and removing the worktree still reach it. If a session for the worktree already exists, it is reused instead of rebuilt. A session that predates the tag is found by its generated name and tagged the first time the start hook sees it. A session tagged for a different worktree that still exists is left alone; an untagged one under this name that points elsewhere is replaced.

The workspace has these windows:

- **Editor**: runs `$EDITOR`, or `nvim` when it is unset, or the `WT_EDITOR` override.
- **Agents**: only when agents were selected explicitly. It starts each installed agent in its own pane, up to four, with a tiled layout.
- **Terminal**: a plain window with two panes, and it is the one selected when you attach.

## Removal: Stop, Then Close

Removal is split in two, because `pre-remove` runs in the worktree that is about to be deleted and `post-remove` runs in the primary worktree afterwards.

```toml
[pre-remove]
tmux = '''
command -v tmux >/dev/null 2>&1 || exit 0
P=storefront
B={{ branch | sanitize }}
W={{ worktree_path }}
S="${P}_$B"
owned_session() {
  for id in $(tmux list-sessions -F '#{session_id}' 2>/dev/null); do
    [ "$(tmux show-options -qv -t "$id" @twt 2>/dev/null)" = "$W" ] && { echo "$id"; return; }
  done
}

find_session() {
  found=$(owned_session)
  [ -n "$found" ] && { echo "$found"; return; }
  tmux has-session -t "=$S" 2>/dev/null || return 0
  found=$(tmux display-message -p -t "=$S:" '#{session_id}')
  [ -z "$(tmux show-options -qv -t "$found" @twt 2>/dev/null)" ] && echo "$found"
  return 0
}

SID=$(find_session)
[ -n "$SID" ] || exit 0

# Collect what runs under each pane. The panes' own shells are left for
# post-remove, because an interactive shell ignores SIGTERM.
PIDS=
collect_tree() {
  for child in $(pgrep -P "$1" 2>/dev/null); do
    PIDS="$PIDS $child"
    collect_tree "$child"
  done
}
for pane in $(tmux list-panes -s -t "$SID" -F '#{pane_id}'); do
  # The pane running this removal must survive it.
  [ "$pane" = "${TMUX_PANE-}" ] && continue
  pane_pid=$(tmux display-message -p -t "$pane" '#{pane_pid}')
  [ -n "$pane_pid" ] && collect_tree "$pane_pid"
done
[ -n "$PIDS" ] || exit 0

kill -TERM $PIDS 2>/dev/null || true
n=0
while [ "$n" -lt 3 ]; do
  LEFT=
  for pid in $PIDS; do
    kill -0 "$pid" 2>/dev/null && LEFT="$LEFT $pid"
  done
  PIDS=$LEFT
  [ -n "$PIDS" ] || exit 0
  n=$((n + 1))
  sleep 1
done
kill -KILL $PIDS 2>/dev/null || true
exit 0
'''
```

`pre-remove` asks every process running under the session's panes to exit, waits up to three seconds, then force-stops what is left. The panes' own shells are left alone because an interactive shell ignores that signal, and the pane running the removal itself is skipped. It never fails: a failing `pre-remove` would cancel the removal.

```toml
[post-remove]
tmux = '''
command -v tmux >/dev/null 2>&1 || exit 0
P=storefront
B={{ branch | sanitize }}
W={{ worktree_path }}
S="${P}_$B"
owned_session() {
  for id in $(tmux list-sessions -F '#{session_id}' 2>/dev/null); do
    [ "$(tmux show-options -qv -t "$id" @twt 2>/dev/null)" = "$W" ] && { echo "$id"; return; }
  done
}

find_session() {
  found=$(owned_session)
  [ -n "$found" ] && { echo "$found"; return; }
  tmux has-session -t "=$S" 2>/dev/null || return 0
  found=$(tmux display-message -p -t "=$S:" '#{session_id}')
  [ -z "$(tmux show-options -qv -t "$found" @twt 2>/dev/null)" ] && echo "$found"
  return 0
}

SID=$(find_session)
[ -n "$SID" ] && tmux kill-session -t "$SID" 2>/dev/null
exit 0
'''
```

`post-remove` ends the session. It finds it by its `@twt` tag, or by the exact generated name for a session that has no tag, and never closes a session tagged for another worktree; the `=` in `-t "=$S"` makes tmux match the whole name, so removing `storefront_fix` can never close a session called `storefront_fix-2`. It uses only Worktrunk's template variables, not the removed directory.

## Choices That Change The File

| Choice           | Effect when off                                                            |
| ---------------- | -------------------------------------------------------------------------- |
| `--no-tmux`      | No tmux, pre-remove, or post-remove hooks, and no tmux notes in the header |
| `--agents` unset | No Agents window and no `WT_AGENTS` override                               |
| `--copy` unset   | No copy hook                                                               |
| `--no-mc`        | No `mc` alias                                                              |
| No start hook    | No `up` alias (that is, tmux off and copy off)                             |

With every choice off, the file is only the header. Agents require tmux, so `--no-tmux` together with `--agents` is an error.

## Adding Your Own Hooks

The generated pipeline is built from `[[pre-start]]` blocks so that yours can sit beside it: add another `[[pre-start]]` block above the tmux block to finish before the session opens, or below it if it can wait. Keys added to an existing table, such as `[post-remove]`, go inside that table rather than under a second header. Run `trunk-cli docs` for the rules, recipes and copyable fragments.
